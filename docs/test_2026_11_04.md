## Problema inicial: Bootstrap de tests roto

### Error
```
Bootstrap migration failed after 50 attempts (exit 1):
SQLSTATE[42S21]: Column already exists: 1060 Duplicate column name 'soil_type_id'
Migration: 2026_03_06_000003_add_lookup_fields_to_plots_table
```

### Causa raíz
MariaDB no hace rollback de DDL (ALTER TABLE) cuando una migración falla a mitad de ejecución. El flujo era:

1. Bootstrap wipe + migrate
2. `2026_03_06_000003` empieza: añade `soil_type_id` a `plots` ✅
3. Algún paso posterior falla (FK o columna problemática)
4. `soil_type_id` queda en la tabla pero la migración no se registra como completada
5. Bootstrap reintenta migrate → `Duplicate column name 'soil_type_id'` → bucle de 50 intentos → crash

### Fix
`database/migrations/2026_03_06_000003_add_lookup_fields_to_plots_table.php` — migración hecha idempotente: cada columna se añade solo si no existe, usando `Schema::hasColumn()` individual por columna.

```php
if (! Schema::hasColumn('plots', 'soil_type_id')) {
    Schema::table('plots', function (Blueprint $table) {
        $table->foreignId('soil_type_id')->nullable()->after('soil_type')->constrained('soil_types')->nullOnDelete();
    });
}
// ... repetido para cada columna
```

**Lección:** En MariaDB/Windows, las migraciones ALTER TABLE que añaden múltiples columnas deben ser idempotentes. Si una falla a mitad, las columnas previas quedan en la tabla y el reintento explota.

### 4. `AuditServiceTest::test_can_clean_old_logs` — Unit
**Error:** `assertGreaterThan(0, $deleted)` devolvía 0 deletions.  
**Causa:** `AuditLog::first()->update(['created_at' => now()->subDays(400)])` es una no-op porque `created_at` no está en `$fillable` de `AuditLog`. Eloquent's `update()` pasa por `fill()` que respeta fillable guards. El `created_at` nunca se actualizaba, así que `cleanOldLogs(365)` no encontraba registros antiguos.  
**Fix en test:**
```php

AuditLog::first()->update(['created_at' => now()->subDays(400)]);

// Después (bypasa fillable guards):
DB::table('audit_logs')->limit(1)->update(['created_at' => now()->subDays(400)]);
```

## Lecciones aprendidas

### MariaDB DDL no es transaccional
Cuando una migración ALTER TABLE falla a mitad, las columnas ya añadidas permanecen. El sistema de retry del bootstrap solo manejaba "Table already exists" (ghost tables), no "Duplicate column name". Solución: hacer idempotentes todas las migraciones ALTER complejas con `Schema::hasColumn()`.

### Eloquent `update()` respeta fillable guards
`$model->update(['created_at' => $value])` es silenciosamente ignorado si `created_at` no está en `$fillable`. Para actualizar campos de timestamp directamente, usar `DB::table(...)→update()` o `$model->forceFill(...)->save()`.

### Seeders afectan tests de conteo
Los tests que usan `assertCount(N, ...)` sobre modelos con seeders fallarán cuando el seeder añada registros del mismo tipo. Preferir assertions de inclusión/exclusión en lugar de counts exactos, o limpiar la tabla en `setUp()`.

### Variables de contexto en views Livewire
Un componente Livewire puede pasar múltiples variables al view. Verificar que el `assertDontSee()` no falla por aparecer en secciones de contexto (alertas, sidebars) en lugar de en la lista principal filtrada.

### `image` → `images` migration
El campo `image` (string) fue migrado a `images` (JSON array) en marzo 2026. Cualquier test o código que aún use `'image' => '...'` en el fillable fallará silenciosamente porque no está en `$fillable`.
